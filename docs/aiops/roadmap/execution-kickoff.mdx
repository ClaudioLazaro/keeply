```text
Keep Evolved = Keep Foundation + AI Control Plane (modular monolith) + MCP Tool Mesh
```

## Working rules

1. Reuse Keep for alerts, incidents, auth, workflows, providers, timeline
2. Build only net-new AIOps capabilities in the AI plane
3. Keep must work with AI plane disabled
4. No mutate tools in MVP
5. Prefer thin Keep PRs for contracts; put product AI logic in `keep-aiops`

## M0 — Architecture spike (now)

**Goal:** incident in Keep → event → read-only investigation → comment/evidence back in Keep.

| # | Task | Outcome |
|---|------|---------|
| 1 | Define event envelope (`incident.created/updated/resolved`) | Contract doc + JSON examples |
| 2 | Keep outbox/webhook spike (thin PR) | Events leave Keep reliably |
| 3 | Scaffold `keep-aiops` modular monolith | `aiops-api` with health + module layout |
| 4 | Keep client (auth + incident/alert read + comment/enrichment write) | Reusable package |
| 5 | Stub MCP Gateway + K8s read tools | `get_pods` / `get_events` / `get_logs` |
| 6 | Orchestrator FSM skeleton (`queued → gathering → rca_ready`) | Persisted investigation |
| 7 | Writeback to Keep timeline | Visible RCA/evidence comment |
| 8 | kind demo + runbook | Reproducible end-to-end |

**M0 exit criteria**

- [ ] Qualifying test incident creates an Investigation idempotently
- [ ] At least one K8s evidence item collected via MCP
- [ ] Keep timeline shows investigation output
- [ ] Stopping `aiops-api` does not break Keep alert ingest
- [ ] OTel trace contains `investigation_id`
