Team assumption: **3–6 engineers**, iterative production-ready delivery. Related: [MVP](/aiops/roadmap/mvp), [PRD-001](/aiops/prd/001-ai-native-aiops-platform).

## Release timeline

```text
M0–M1   Foundations + event bridge + shadow investigations
M2–M4   MVP investigate/RCA/RAG → multi-agent MCP → approvals
M5–M7   Controlled execution → postmortems → enterprise hardening
M8–M18  Scale, eval quality, more agents, upstream maturity
```

---

## Milestone 0 — Architecture spike

| Field | Detail |
|-------|--------|
| **Goal** | Prove external investigator with minimal Keep changes |
| **Duration** | 2–3 weeks |
| **Complexity** | M |
| **Order** | 1 |

**Scope:** Event bridge prototype; one read-only K8s MCP; investigation record; comment back to incident.

**Technical tasks:**
- Outbox/webhook spike PR against Keep
- `keep-client` package
- Orchestrator skeleton + kind demo

**Dependencies:** Keep API token; cluster read SA  
**Risks:** Event reliability; auth propagation  

**Acceptance criteria:**
- Test incident produces timeline comment with pod evidence

## Suggested implementation order

1. Event bridge + outbox PR  
2. AIOps DB + orchestrator FSM (suggest-only)  
3. Context Builder + Keep client  
4. MCP gateway + K8s/Obs read servers  
5. Knowledge MVP  
6. RCA draft → Keep timeline  
7. UI investigation panel  
8. Eval harness  
9. Policy engine + approval UX  
10. Execution allowlist  
11. Postmortems + learning  
12. Expand agents/clouds
