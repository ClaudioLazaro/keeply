ADRs record **why** a significant technical decision was made. They are immutable once accepted; superseding decisions get a new ADR.

## Format

Use the [ADR template](/aiops/adr/0000-template). Status values: `Proposed`, `Accepted`, `Deprecated`, `Superseded`.

## When to write an ADR

Write an ADR when choosing:

- Service boundaries or deployment topology
- Security/policy defaults
- Event/data contracts that multiple teams depend on
- Something expensive to reverse

Do **not** write ADRs for routine implementation choices (library minor versions, file layout tweaks).
